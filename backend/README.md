# Архитектура backend

Публичный API сохранен прежним, но исходная логика MVP разделена на небольшие слои:

- `config.py` читает переменные окружения и собирает инфраструктурные URL.
- `database.py` отвечает за async SQLAlchemy engine и FastAPI-зависимость сессии.
- `storage.py` потоково сохраняет загруженные файлы и изолирует работу с путями.
- `repositories.py` содержит запросы к базе данных.
- `processing.py` содержит чистую логику сканирования, извлечения метаданных и сборки алертов.
- `service.py` координирует транзакции и бизнес-сценарии.
- `tasks.py` запускает обработку файла в Celery.

Основная оптимизация: старая цепочка из трех Celery-задач заменена на одну фоновую задачу на файл. Сканирование, извлечение метаданных и создание алерта остались отдельными функциями, но worker больше не отправляет два лишних сообщения в Redis и не загружает одну и ту же запись в трех независимых задачах.

Эндпоинты остались прежними.
